# SnipeIT Inventory Agent - Change log v1.3.2

Дата выпуска: 4 августа 2026

## Точное представление скорости RAM

В версии 1.3.2 исправлено отображение скорости оперативной памяти. Агент
перестал вычислять условную частоту RAM делением DDR-скорости на два и
подписывать результат как \`MHz clock\`.

Современные структуры SMBIOS передают значения как число миллионов передач в
секунду, то есть \`MT/s\`. Производители ноутбуков могут по-разному заполнять
эти поля, поэтому производная величина не должна выдаваться за прямое
аппаратное измерение.

## Штатный источник данных

Агент получает информацию стандартным API Windows:

\`\`\`powershell
Get-CimInstance Win32_PhysicalMemory
\`\`\`

Из BIOS/SMBIOS используются исходные значения:

- \`Capacity\` — размер модуля;
- \`Manufacturer\` и \`PartNumber\` — производитель и номер модуля;
- \`SMBIOSMemoryType\` — DDR4, DDR5, LPDDR5 и другой тип;
- \`FormFactor\`, \`DeviceLocator\`, \`BankLabel\` — тип и расположение;
- \`ConfiguredClockSpeed\` — скорость, настроенная BIOS;
- \`Speed\` — заявленная SMBIOS скорость модуля.

Значения \`ConfiguredClockSpeed\` и \`Speed\` сохраняются без пересчёта и
отображаются как \`MT/s\`.

## Новый формат

При одинаковых configured и module значениях:

\`\`\`text
Micron Technology+Samsung 32 GB DDR5; 5600 MT/s; 2 x 16 GB; 2/2 SODIMM slots used
\`\`\`

Если BIOS сообщает разные значения:

\`\`\`text
Micron Technology 16 GB LPDDR5; configured 5200 MT/s; module 6400 MT/s; onboard
\`\`\`

Для распаянной памяти используется отдельная запись:

\`\`\`text
Onboard/soldered; no user-replaceable DIMM/SODIMM slots
\`\`\`

## Что не менялось

- Агент не устанавливает драйверы и не читает SPD через vendor-specific API.
- State остаётся версии \`3\`.
- Формат relay payload остаётся совместимым.
- Закрытый JSON ветки \`1.3.x\` совместим с агентом \`1.3.2\`.
- \`asset_tag\` по-прежнему не создаётся и не перезаписывается агентом.

## Обновление и проверка

После замены файлов установщик сравнивает SHA-256 и обновляет агент только
при реальном отличии версии или содержимого. Переход \`1.3.1 -> 1.3.2\`
создаёт одно событие \`install_update\`; повторный запуск с теми же файлами
идемпотентен и не создаёт лишних писем.

Проверены синтаксис PowerShell, сбор RAM на ноутбуках с SODIMM и распаянной
LPDDR, совместимость state и relay, а также отсутствие перезаписи
инвентарного тега.
