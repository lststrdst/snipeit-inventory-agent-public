# SnipeIT Inventory Agent 1.3.2

Дата: 4 августа 2026

## Зачем выпущена 1.3.2

Версия исправляет отображение скорости оперативной памяти. Агент больше не вычисляет условную частоту RAM делением скорости DDR на два и не подписывает вычисленное значение как `MHz clock`.

Такой расчёт был лишним: современные структуры SMBIOS Memory Device передают скорость памяти как количество миллионов передач в секунду (`MT/s`). Кроме того, производители ноутбуков могут по-разному заполнять эти поля, поэтому производная величина не должна выдаваться за аппаратное измерение.

## Прямой сбор RAM

Источник остаётся штатным и не требует сторонних драйверов:

```powershell
Get-CimInstance Win32_PhysicalMemory
```

Агент напрямую использует значения, полученные от BIOS/SMBIOS:

- `Capacity` — объём модуля;
- `Manufacturer` — производитель;
- `PartNumber` — номер модуля;
- `SMBIOSMemoryType` — DDR4, DDR5, LPDDR5 и другие типы;
- `FormFactor` — DIMM, SODIMM или распаянная память;
- `DeviceLocator` и `BankLabel` — расположение;
- `ConfiguredClockSpeed` — настроенная BIOS скорость памяти;
- `Speed` — скорость, заявленная для модуля в SMBIOS.

Числа из `ConfiguredClockSpeed` и `Speed` сохраняются без пересчёта и показываются как `MT/s`.

## Новый формат

Если настроенная и заявленная скорости совпадают:

```text
Micron Technology+Samsung 32 GB DDR5; 5600 MT/s; 2 x 16 GB; 2/2 SODIMM slots used
```

Если BIOS сообщает разные значения:

```text
Micron Technology 16 GB LPDDR5; configured 5200 MT/s; module 6400 MT/s; onboard
```

Это означает:

- `configured` — значение `ConfiguredClockSpeed`, с которым BIOS настроил память;
- `module` — значение `Speed`, указанное SMBIOS для модуля;
- агент не делает выводов о физической частоте и не делит значения на два.

Для распаянной памяти сохраняется отдельное представление:

```text
Onboard/soldered; no user-replaceable DIMM/SODIMM slots
```

## Что принципиально не делается

Агент не устанавливает низкоуровневый SMBus-драйвер и не читает SPD напрямую через vendor-specific API. Такой подход потребовал бы дополнительного драйвера с повышенными привилегиями и увеличил бы риск развёртывания через GPO.

Штатный источник Windows получает данные из BIOS/SMBIOS. Если прошивка конкретного ноутбука заполнила SMBIOS неправильно, агент сохраняет исходные значения и не пытается «исправить» их догадкой.

## Совместимость

- Версия state остаётся `3`.
- Формат relay payload остаётся совместимым.
- IMAP-коллектор `1.3.1` менять не требуется.
- Закрытый JSON ветки `1.3.x` полностью совместим с агентом `1.3.2`.
- Токены, SMTP-пароль и HMAC-секрет менять не требуется.
- `asset_tag` по-прежнему не создаётся и не перезаписывается агентом.

## Обновление через GPO

После замены публичных файлов установщик увидит новый SHA-256 и версию `1.3.2`, обновит локальный агент и выполнит штатный `DeploymentRun`.

Переход `1.3.1 -> 1.3.2` создаёт одно событие `install_update` и один forced-report. Повторный запуск установщика с теми же файлами идемпотентен и дополнительных писем не создаёт.

## Проверки выпуска

Для версии добавлен отдельный RAM-тест, который проверяет:

- сохранение прямых значений `5200/6400 MT/s`;
- отсутствие `MHz`, `2600`, `2800` и `3200`, полученных делением;
- корректное определение распаянной памяти;
- корректное отображение двух SODIMM;
- сбор реальных данных RAM на тестовом ноутбуке.
