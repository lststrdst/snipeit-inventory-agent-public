# SnipeIT Inventory Agent

Я разработал этот проект, потому что мне была нужна инвентаризация Windows-
компьютеров, которая продолжает работать, даже когда устройство находится вне
локальной сети и не видит внутренний DNS или API Snipe-IT.

Это обезличенная версия моей рабочей системы. В ней сохранены код, архитектура,
примеры конфигурации, сценарии развертывания и тесты, но удалены сведения о
реальной инфраструктуре и все секреты. Текущий опубликованный релиз — `1.3.3`.

## Какую проблему решает проект

Ноутбук не всегда находится в офисе: пользователь может работать удаленно, не
подключать VPN или получить другое устройство. Если агент умеет обращаться
только к внутреннему API, инвентаризация в такие моменты просто пропадает.

Я добавил резервный почтовый транспорт:

```text
Windows Agent -> Snipe-IT API
       |
       `-> SMTP -> IMAP Relay -> локальный Snipe-IT API

Directory service -> определение владельца и offboarding
Maintenance       -> склад, очистка и weekly report
```

При доступном API агент обновляет актив напрямую. При сетевой ошибке он
отправляет подписанное JSON-событие через SMTP. IMAP relay на сервере проверяет
событие и применяет его через локальный API. Если почта временно недоступна,
агент сохраняет событие в локальной очереди и повторяет отправку позже.

## Возможности

- сбор модели, серийного номера, CPU, RAM, дисков и версии Windows;
- определение фактического интерактивного пользователя;
- создание и обновление активов Snipe-IT;
- checkout новому владельцу и безопасный возврат на склад;
- защита от дублей через стабильный `event_id`;
- HMAC-проверка offline-событий;
- IMAP-сортировка отчетов, предупреждений, ошибок и relay-событий;
- серверный offboarding отключенных пользователей;
- недельный отчет по компьютерам без свежей инвентаризации;
- скрытая установка и обновление агента через GPO;
- dry-run и автоматические тесты.

## Состав репозитория

- `01-Agent-PUBLIC` — PowerShell-агент и установщик.
- `03-Relay-PUBLIC` — Python IMAP relay и systemd units.
- `05-Maintenance-PUBLIC` — серверное обслуживание и отчеты.
- `08-Documentation` — архитектура, эксплуатация и changelog.
- `09-Tests` — набор проверок Windows- и серверной частей.

## Безопасность и анонимизация

Я намеренно не публикую production JSON, токены API, почтовые пароли,
HMAC-секреты, SSH-ключи, внутренние адреса, доменные имена, структуру каталогов,
SQLite-базы, логи и реальные снимки экранов. В примерах используются только
нейтральные placeholders. Реальные значения должны храниться в закрытом
окружении с минимальными правами и корректными ACL.

HMAC защищает событие от подмены, но не шифрует его содержимое. Прямой API-
доступ на клиентах также увеличивает потенциальный ущерб при компрометации
устройства. Эти ограничения относятся к архитектуре `1.3.3` и честно
зафиксированы в документации.

## Дальнейшее развитие

Эту ветку я сохраняю как законченную историю агента `1.3.3`. Новую архитектуру
я развиваю отдельно под названием **SnipeIT Inventory Gateway**: API token
остается только на сервере, а клиент отправляет зашифрованное событие по HTTPS
с резервной доставкой через почту.

Подробности текущей версии находятся в
`08-Documentation/ARCHITECTURE-RU.md` и
`08-Documentation/CHANGELOG-1.3.3-RU.md`.
